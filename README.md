## מדריך לימי האולם (1-3.12.26)
**בעל צימר בטאבלט/טלפון:** רישום ← הנחיות ← בחירה ← סיכום ← שליחה. אחרי שליחה מוצלחת מופיע מספר הזמנה, נשלח מייל עם Excel (לצוות + עותק ללקוח), ואחר כך יורדים Excel ו-PDF למכשיר. באייפד/אייפון אין הורדה אוטומטית - יש כפתורי "הורדת Excel" / "הורדת PDF". המכשיר מתנקה לבד.

**טאבלט משותף:** בין לקוח ללקוח - "↺ לקוח חדש" (בכותרת) או "סיום - לקוח חדש" במסך האישור. מסך האישור חוזר לבד לרישום אחרי 10 דקות.

**מה הלקוח עשוי לראות, ומה עושים:**
| הודעה | מה זה | מה עושים |
|---|---|---|
| "בודק מלאי..." | המלאי העדכני נטען (2-3 שניות) | לחכות |
| "אזל מהמלאי" / "זו הכמות המקסימלית הזמינה" | אין יותר במלאי | לבחור פריט אחר |
| "חלק מהפריטים כבר לא זמינים בכמות שביקשת" | מישהו אחר הזמין בינתיים | ללחוץ "עדכון לכמות המקסימלית הזמינה" ולשלוח שוב |
| "המערכת עמוסה, נסו שוב בעוד רגע" | כמה הזמנות בדיוק באותו רגע | ללחוץ שוב על שליחה. העגלה שמורה |
| "כבר נשלחה הזמנה ממספר הטלפון הזה" | הזמנה אחת לצימר | שינוי רק דרך הצוות: לבטל את הישנה במסך הניהול, והצימר שולח חדשה |
| "לא התקבלה תשובה מהשרת" | נפל האינטרנט | לבדוק חיבור וללחוץ שוב. אם ההזמנה כבר נקלטה, תופיע הודעה על כך ולא תיווצר כפולה |
| "האישור במייל יישלח בדקות הקרובות" | ההזמנה נקלטה, המייל בטיפול בשרת | כלום. אם אחרי 5 דקות עדיין "ממתין" במסך הניהול - "שלח שוב" |
| "המייל לא נשלח כרגע" | ההזמנה נקלטה, המייל לא | במסך הניהול ← הזמנות ← "שלח שוב" |

**שינוי בהזמנה של צימר:** אין עריכה. מבטלים במסך הניהול (המלאי חוזר מיד), והצימר שולח הזמנה חדשה מאותו טלפון.

**אם משהו לא עובד בכלל:**
- האתר לא נטען / "אין חיבור למלאי": לבדוק אינטרנט. לפתוח את כתובת השרת עם `?action=catalog` (ראו "הגיליון והשרת" למטה) - אם מופיע `"ok":true`, השרת תקין.
- שגיאת הרשאה: בעורך Apps Script להריץ `setupSheet`, לאשר את כל ההרשאות, ולפרוס גרסה חדשה.
- כמה נמעני מייל נשארו היום: במסך הניהול (מדד "מיילים שנותרו היום") או `checkAccount` מהעורך.

- **הקוד:** `apps-script.js` מודבק בגיליון, דרך תוספים ← Apps Script.
- **כתובת השרת (Web app):**
  `https://script.google.com/macros/s/AKfycbynZDBWrzSYNvW6bsdgW3KMWGpIV8maveVTKufv3JilsuD_LYD7d5OxK5h4vuzVMQnMIg/exec`

- **חשבון:** Workspace, עם מכסה של 1,500 נמעני מייל ביום (כ-375 הזמנות).

### הלשוניות
| לשונית | מה יש בה | מי מעדכן |
|---|---|---|
| מוצרים | שורה לכל מוצר: מחיר, תיאור, מלאי התחלתי, **יתרה**, פעיל | הצוות מעדכן מחירים, תיאורים ו"פעיל". את **היתרה** לא משנים ידנית - רק דרך מסכי הניהול, כדי שכל שינוי יירשם ביומן |
| הגדרות | תקציב, נמעני מייל, סף מלאי נמוך, פתוח להזמנות | הצוות |

- "ללא הגבלה" = כן: המוצר מוזמן מהספק, ואין בדיקת מלאי.

### אחרי כל שינוי בקוד ה-Apps Script
1. להדביק את הקוד החדש ולשמור.
2. פריסה ← ניהול פריסות ← עיפרון ← גרסה: **גרסה חדשה** ← פריסה.
3. הכתובת לא משתנה. בלי השלב הזה, האתר ימשיך להריץ את הקוד הישן.

### הגדרות הפריסה (אם יוצרים פריסה מאפס)
- סוג: אפליקציית אינטרנט.
- לבצע בתור: **עצמי**.
- למי יש גישה: **כל אחד**. לא "כל מי שיש לו חשבון Google".
- אם מופיעה השגיאה "אין לך הרשאה להתקשר אל SpreadsheetApp": להריץ מהעורך את `setupSheet`, לאשר את **כל** תיבות ההרשאה, ולפרוס גרסה חדשה.

## האתר (`index.html`)
הזרימה: רישום ← הנחיות ← קטלוג בטאבים ← סיכום ← שליחה ← מסך אישור.

**איך המלאי מוצג:**
- הקטלוג מוצג מיד מעותק שמור: העותק החי האחרון שנשמר בדפדפן, ואם אין כזה, הקובץ `data/catalog-snapshot.json`.
- **עד שהמלאי העדכני מהשרת מגיע, אי אפשר להוסיף לעגלה.** הכפתורים מסומנים "בודק מלאי...".
- המלאי מתרענן כל דקה, וגם במעבר לסיכום או בחזרה ללשונית. אם פריט שבעגלה ירד במלאי, הכמות בעגלה מתעדכנת ומופיעה הודעה.
- אם השרת לא עונה, מופיעה הודעה עם כפתור "נסו שוב", והאתר מנסה שוב אוטומטית.
- **ללקוח לא מוצגות כמויות.** בכרטיס מופיע רק "במלאי", "אזל מהמלאי" (והכפתור נעול) או "בהזמנה מהספק" לפריטים ללא הגבלת מלאי. הכמויות מוצגות רק במסכי הניהול.
- ההגבלה לפי המלאי נשארת: כשמגיעים לכמות המקסימלית, כפתור ה-+ ננעל ומופיעה ההודעה "זו הכמות המקסימלית הזמינה", בלי מספר.

**שולחנות:** בטאב "בנה שולחן" בוחרים רגל, גוון וקוטר. הכמות מוגבלת לנמוך מבין מלאי הרגל ומלאי הפלטה, ורגל שכבר נמצאת בשולחן אחר בעגלה נספרת.
- בכל מקום שההזמנה מוצגת, שולחן הוא שורה אחת: תמונת הרגל + תמונת הפלטה, התיאור "שולחן: רגל LP2 + פלטה אגוז קוטר 80", ופירוט "רגל LP2: ₪799 · פלטה אגוז 80 ס"מ: ₪... · סה"כ לשולחן: ₪...".
- בגיליון ("פריטי הזמנה") שולחן נשמר כ-2 שורות, רגל ופלטה, עם אותו תיאור בעמודת "פירוט". כך הריכוזים והמלאי הם לפי מק"ט. המייל, ה-Excel ומסך הניהול מחברים אותן חזרה לשורה אחת.

**חריגה מהתקציב:** הפס מתמלא בירוק, בזהב מ-80% ובאדום מעל התקציב. אפשר לשלוח הזמנה בחריגה רק אחרי סימון "אני מאשר/ת".

**פס הקטגוריות:** דבוק למעלה בזמן גלילה.
- מרוחב 700px (טאבלט ומחשב) כל הקטגוריות גלויות, ואם צריך הן נשברות לשתי שורות.
- בטלפון הפס נגלל בהחלקה, עם טשטוש וחץ בקצה שבו יש עוד קטגוריות. הקטגוריה הפעילה נגללת אוטומטית לתוך התצוגה.

**נשמר בדפדפן:** הפרטים והעגלה נשמרים, כך שרענון או סגירה בטעות לא מוחקים אותם. זו נוחות בלבד, ואין שריון מלאי לפני שליחה.

**טאבלט משותף באולם:**
- הכפתור "↺ לקוח חדש" בכותרת מוחק מהמכשיר את העגלה ואת פרטי הצימר, אחרי אישור.
- אחרי שליחה מוצלחת המחיקה נעשית אוטומטית, ומסך האישור חוזר לבד לרישום אחרי 10 דקות.

**מובייל:** נבדק אוטומטית ברוחב 375px וברוחב 768px.
- אין גלילה אופקית.
- אין טקסט קטן מ-12px.
- כל כפתור הוא לפחות 36px, ורוב הכפתורים 44px.

**הגדרות בקוד** (`CONFIG` בראש הסקריפט ב-`index.html`): כתובת השרת, תדירות רענון המלאי, והודעות המלאי ללקוח (`MAX_MSG`, `OUT_MSG`).

### עדכון האתר באוויר
כל שינוי בקבצים עולה לאתר אחרי `git push` (לוקח 1-2 דקות). בדיקה אוטומטית מול האתר החי:
```
cd tools
SITE_URL=https://dafi-k.github.io/mevoot-hermon-orders/ node test-client.js
```

### בדיקה מקומית
```
cd tools
node serve.js            # ואז לפתוח http://localhost:8080
node test-client.js      # בדיקת תצוגה ב-375px וב-768px (דורש את השרת המקומי פועל)
node test-server.js      # בדיקת קוד השרת עם הדמיה של Google
node test-submit.js      # בדיקת שליחה מקצה לקצה: דפדפן + קוד השרת בהדמיה
node test-admin.js       # בדיקת מסכי הניהול מקצה לקצה
node test-mail-backup.js # Excel שהשרת בונה, גיבוי "ממתין" אחרי 2 דקות, שליחה חוזרת, שולחן במייל/Excel
node test-ipad.js        # שליחה מאייפד ב-WebKit (המנוע של Safari), כולל שחזור התקלה בגרסה הקודמת
```
ל-`test-ipad.js` צריך פעם אחת: `npx playwright-core install webkit`.

## שליחת הזמנה (שלב 4)
**מה קורה בלחיצה על "שליחה":**
1. האתר שולח לשרת **רק מזהים וכמויות**. השרת מחשב מחירים, סה"כ וחריגה לפי הגיליון בלבד, ומתעלם מכל מחיר שמגיע מהאתר.
2. בתוך נעילה (LockService), כך ששני לקוחות לא יקבלו את אותה יחידה אחרונה:
   - בודק שלטלפון אין הזמנה פעילה (הזמנות "בוטלה" לא נספרות).
   - בודק מלאי. **אם חסר - שום דבר לא נכתב**, והלקוח רואה אילו שורות חסרות (בלי מספרים) וכפתור "עדכון לכמות המקסימלית הזמינה".
   - כותב את ההזמנה, מוריד יתרות ורושם תנועות ביומן.
   - אם הנעילה תפוסה יותר מ-25 שניות: "המערכת עמוסה, נסו שוב בעוד רגע", והעגלה נשמרת.
3. האתר מוחק מהמכשיר את העגלה ואת פרטי הרישום, ובונה Excel (עם תמונות מוקטנות) בזיכרון.
4. **בקשה נפרדת** שולחת את ה-Excel לשרת: הקובץ נשמר ב-Drive (תיקייה "הזמנות מבואות החרמון - קבצים"), ונשלח מייל לצוות עם CC ללקוח.
   - **הבקשה יוצאת לפני כל הורדה למכשיר.** בספארי באייפד הורדת קובץ מחליפה או מקפיאה את הדף, ומה שהדף היה אמור לשלוח אחריה לא נשלח (זו הייתה התקלה ב-MH-261123-006/007).
   - אם הבקשה נקטעת: עוד 2 ניסיונות (אחרי 2 ו-5 שניות). השרת לא שולח את אותו מייל פעמיים, גם אם שתי בקשות הגיעו.
   - אם לא הגיע קובץ מהאתר, השרת בונה את ה-Excel בעצמו מהגיליון.
5. רק אחרי שהשרת ענה: במחשב ובאנדרואיד יורדים Excel ו-PDF אוטומטית. באייפד/אייפון לא, ויש כפתורי הורדה שפותחים את הקובץ בלשונית חדשה, כך שדף האישור נשאר.

**גיבוי בשרת (טריגר `mailWatchdog`, כל דקה):** הזמנה שנשארה "ממתין" יותר מ-2 דקות (למשל הטאבלט נסגר מיד אחרי השליחה) - השרת בונה Excel מהגיליון ושולח את המייל. בעמודה "סטטוס מייל" יופיע "נשלח ... (גיבוי אוטומטי)".
- מותקן פעם אחת מהעורך: להריץ `installMailWatchdog` ולאשר את ההרשאות. בטוח להריץ שוב.
- הגיבוי מטפל רק בהזמנות שנוצרו אחרי ההתקנה. הזמנות בדיקה ישנות שנשארו "ממתין" לא יישלחו פתאום.
- Excel שהשרת בונה: אותם פרטים ושורות כמו ב-Excel מהאתר, עם תמונות מוקטנות מ-`pic/thumbs/` באתר הציבורי.

**מספרי הזמנה:** `MH-שנהחודשיום-מספר` (למשל MH-261201-014). הזמנת בדיקה: `TEST-...`.

**ניתוק באמצע שליחה:** אם התשובה מהשרת לא הגיעה, הלקוח יכול ללחוץ שוב. אם ההזמנה כבר נקלטה, השרת מזהה את הטלפון ולא נוצרת הזמנה כפולה.

### הזמנות בדיקה (כש"פתוח להזמנות" = לא)
- בלשונית "הגדרות" יש **קוד בדיקה** (נוצר אוטומטית בהרצת setupSheet).
- פותחים את האתר עם הקוד: `https://dafi-k.github.io/mevoot-hermon-orders/?test=הקוד`
- מופיע "מצב בדיקה", וההזמנה נשמרת עם מספר TEST ו"הזמנת בדיקה" בעמודת הערות צוות. המייל מסומן [בדיקה].
- הקוד עובד גם כשהאתר פתוח: הזמנה דרך קישור הבדיקה תסומן TEST.
- "לקוח חדש" (או "סיום - לקוח חדש") מבטל את מצב הבדיקה במכשיר. להזמנת בדיקה נוספת פותחים שוב את קישור הבדיקה.
- **אחרי הבדיקות מוחקים את "קוד בדיקה" בהגדרות** (ראו רשימת התיוג למעלה).
- **הזמנת בדיקה מורידה מלאי אמיתי.** אחרי הבדיקה מבטלים אותה במסכי הניהול, והמלאי חוזר.

### מייל שלא נשלח
- בעמודה "סטטוס מייל" בלשונית הזמנות: "ממתין", "נשלח + תאריך" או "לא נשלח: סיבה" (למשל מכסה יומית). אחרי "נשלח" יכול להופיע ממי: "(גיבוי אוטומטי)" או "(שליחה חוזרת - שם העובד)".
- שליחה חוזרת: כפתור "שלח שוב" במסך ההזמנות בניהול. אם אין להזמנה קובץ Excel ב-Drive, השרת בונה אותו מהגיליון ומצרף.
- הזמנה שהמייל שלה נשלח בלי Excel מקבלת במסך הניהול כפתור **"שלח שוב עם Excel"**.
- אפשר גם להריץ מהעורך את `resendFailedEmails`: שולחת שוב כל מייל שלא נשלח, עם Excel.
- `checkAccount` מהעורך מראה כמה נמענים נותרו היום וכמה נשלחו.

## מסכי ניהול (שלב 5)
כתובת: **https://dafi-k.github.io/mevoot-hermon-orders/admin.html** (לא מקושר מהאתר, ולא מופיע במנועי חיפוש).

**כניסה:** שם + סיסמה משותפת לצוות.
- הסיסמה נבדקת בשרת ושמורה ב-Apps Script: ⚙️ הגדרות הפרויקט ← מאפייני סקריפט ← `ADMIN_PASSWORD`. היא לא מופיעה בקוד.
- כדי להחליף סיסמה: משנים את הערך שם ושומרים. אין צורך בפריסה חדשה.
- אחרי 10 ניסיונות שגויים הכניסה נחסמת ל-10 דקות.
- הכניסה תקפה 8 שעות או עד "יציאה". השם שנכתב בכניסה נרשם ביומן התנועות בכל פעולה.

**המסכים:**
| מסך | מה יש בו |
|---|---|
| מלאי | לכל מוצר: מלאי התחלתי, נכנס, הוזמן, תיקונים, יתרה. סימון אדום לאזל, צהוב למלאי נמוך (לפי "סף מלאי נמוך" בהגדרות). כפתורי "+ כניסה" ו"תיקון" |
| כניסת סחורה | מוצר, כמות, תאריך קבלה והערה. היתרה מתעדכנת מיד ומופיעה באתר תוך דקה |
| הזמנות | חיפוש וסינון לפי סטטוס, "מייל לא נשלח" ו"בדיקה". שינוי סטטוס (חדשה / אושרה / סופקה / בוטלה), "שלח שוב" למייל, קישור לקובץ ה-Excel ופירוט פריטים עם תמונות (שולחן = שורה אחת עם רגל + פלטה) |
| ריכוז כמויות | כמה יחידות הוזמנו מכל פריט, בהזמנות שלא בוטלו |
| סיכום לפי צימר | סה"כ, תקציב, יתרה וחריגה לכל צימר |
| יומן תנועות | כל שינוי במלאי: תאריך ושעה, מי, סוג, כמה, יתרה אחרי, הפניה והערה |

**ביטול הזמנה** מחזיר את כל הכמויות למלאי (ונרשם ביומן כ"ביטול"). הזמנה שבוטלה לא חוזרת, והצימר יכול לשלוח הזמנה חדשה מאותו טלפון.

**תיקון ידני** קובע יתרה חדשה, וחובה לכתוב סיבה. **לא משנים את עמודת "יתרה" ישירות בגיליון.** אם זה קרה, המוצר יסומן "לא עקבי" במסך המלאי (מלאי התחלתי + התנועות ביומן לא שווה ליתרה). מתקנים דרך "תיקון".

**"כולל הזמנות בדיקה בסיכומים":** כשהאתר סגור, הסימון מופעל כברירת מחדל. הזמנות בדיקה מופיעות תמיד ברשימת ההזמנות, מסומנות "בדיקה", כדי שאפשר יהיה לבטל אותן.

**לשוניות בגיליון:** "ריכוז כמויות" ו"סיכום לפי צימר" מחושבות אוטומטית (נוסחאות QUERY, בלי הזמנות שבוטלו ובלי הזמנות בדיקה). לא לערוך אותן ידנית, ולא לשנות את סדר העמודות בלשוניות "הזמנות" ו"פריטי הזמנה", כי הנוסחאות תלויות בו.

**תאריכים:** בלשוניות הזמנות, פריטי הזמנה ותנועות מלאי, התאריך נרשם עם שעה (dd/MM/yyyy HH:mm).

## איך המוצרים מזוהים
לכל מוצר יש **מזהה ייחודי** (עמודה "מזהה"). המזהה הוא המפתח בכל המערכת: עגלה, מלאי, הזמנות ושם קובץ התמונה.
לא משתמשים בקוד או במק"ט כמפתח, כי הם חוזרים על עצמם (P1 הוא גם כיסא פלסטיק וגם פלטה, M1 הוא גם מראה וגם משוטים, ול-OD23/OD27 יש אותו מק"ט).

| לשונית באקסל | דוגמת מזהה |
|---|---|
| כיסאות פלסטיק | `CH-P1` |
| כורסאות | `AR-A1` |
| כיסאות פינת אוכל | `DC1` |
| כיסאות בר | `BC1`, `BC-P16` |
| שולחנות קפה | `CT1` |
| מראות | `MR-M1` |
| רגלי ברזל | `LG-LP1` |
| פלטות | `TOP-P1` (התמונה משותפת לפי גוון: `TOP-black` / `TOP-walnut` / `TOP-natural`) |
| שולחנות חוץ/פנים | `OT1` |
| אחר | `MS-H1`, `MS-M1` |
| ריהוט חוץ | `OD1` ... `OD73` |

**מלאי:** אם עמודת הכמות באקסל ריקה, המוצר מסומן "ללא הגבלה" (כל ריהוט החוץ ומזרן MT1 - בהזמנה מהספק).

## הרצה מחדש של הייבוא (רק אם האקסל המקורי השתנה לפני העלייה לאוויר)
```
cd tools
npm install
node import-catalog.js
node make-review.js
```
המקור: `..\אתר הזמנות מבואות החרמון - מעודכן תמונות.xlsx` והתיקיות שעמודה I מפנה אליהן. את המקורות הסקריפט רק קורא, ולא משנה.

תיקונים שאושרו אחרי הבדיקה נשמרים ברשימה `CORRECTIONS` בתחילת `tools/import-catalog.js`, ולא באקסל המקורי. נכון ל-22.11.26 יש תיקון אחד: CH-P3 בצבע ירוק (באקסל רשום קרם).

> אחרי שהגיליון באוויר, **מחירים, תיאורים ומלאי מעדכנים בגיליון בלבד** ולא מריצים את הייבוא שוב.
